# АртКлассы — фронтенд

SPA-клиент системы бронирования мастер-классов: каталог с фильтрами, запись и лист
ожидания, кабинет мастера с модерацией, админ-панель.

**Стек:** React 18 · Vite 5 · Bootstrap 5 (react-bootstrap) · Axios · React Router 6

---

## Быстрый старт (без Docker)

```bash
npm install
npm run dev        # http://localhost:5173
```

Бэкенд должен быть запущен на `http://localhost:8000` (см. корневой docker-compose
проекта). Все запросы к `/api` Vite в dev-режиме автоматически проксирует на бэкенд —
никаких CORS-настроек не требуется.

## Переменные окружения

Скопируйте `.env.example` в `.env`, если нужно нестандартное подключение:

| Переменная          | По умолчанию | Описание                                                                 |
| ------------------- | ------------ | ------------------------------------------------------------------------ |
| `VITE_API_BASE_URL` | `/api`       | База API. `/api` работает через прокси (Vite в dev, nginx в Docker).      |
| `VITE_PROXY_TARGET` | `http://localhost:8000` | Цель dev-прокси Vite (если бэкенд на другом порту).            |

Пример прямого подключения (минуя прокси):

```
VITE_API_BASE_URL=http://localhost:8000/api
```

При этом в `CORS_ORIGINS` бэкенда должен присутствовать адрес фронтенда —
по умолчанию там уже указаны `http://localhost:3000` и `http://localhost:5173`.

## Запуск в Docker

В корневом `docker-compose.yml` проекта уже есть заготовка сервиса `front` —
раскомментируйте её:

```yaml
  front:
    build: ./front
    ports:
      - "3000:3000"
    depends_on:
      - back
```

и выполните:

```bash
docker compose up --build front
```

Приложение будет доступно на **http://localhost:3000**. Внутри контейнера nginx
проксирует `/api` на сервис `back:8000`, поэтому CORS не используется вовсе.

> Первый администратор создаётся бэкендом автоматически из переменных
> `FIRST_ADMIN_EMAIL` / `FIRST_ADMIN_PASSWORD` корневого docker-compose.

## Жизненный цикл мастер-класса

```
черновик (draft) ──отправка──> на модерации (pending) ──одобрен──> опубликован (published) ──автоматически──> завершён (finished)
      ▲                              │
      └────── исправлен ──── отклонён (rejected)
```

Отменённый (`cancelled`) МК нельзя восстановить: все активные брони аннулируются.

## Структура проекта

```
front/
├── Dockerfile              # двухэтапная сборка: node -> nginx
├── nginx.conf              # статика + прокси /api на back:8000, порт 3000
├── .env.example            # пример переменных окружения
├── index.html
└── src/
    ├── api/                # axios-клиент (JWT, 401-интерцептор) и эндпоинты
    ├── context/            # AuthContext (вход/сессия), ToastContext (уведомления)
    ├── components/
    │   ├── layout/         # шапка, подвал
    │   ├── ui/             # бейджи статусов, пагинация, модалки, звёзды рейтинга…
    │   └── workshop/       # карточка МК, список отзывов
    ├── pages/
    │   ├── HomePage        # каталог с фильтрами (поиск, категория, цена, даты)
    │   ├── WorkshopPage    # карточка МК: запись, места, отзывы
    │   ├── MasterPublicPage# публичный профиль мастера
    │   ├── MyBookingsPage  # брони клиента: отмена, отзыв
    │   ├── master/         # кабинет мастера: CRUD МК, участники
    │   ├── admin/          # админ-панель: 5 разделов
    │   └── …               # вход, регистрация, профиль, 404
    ├── utils/              # форматирование дат/цен, справочники статусов
    └── styles/theme.css    # минимальные кастомизации поверх Bootstrap
```

## Особенности реализации

- **JWT-сессия.** Токен и профиль хранятся в `localStorage`; интерцептор axios при
  любом ответе `401` разлогинивает и переводит на `/login?expired=1`. Вход/регистрация
  из перехвата исключены, чтобы показывать ошибки формы.
- **Защита маршрутов.** Компонент `ProtectedRoute` скрывает разделы по ролям;
  сервер при этом остаётся единственным источником истины.
- **Лист ожидания.** Если мест нет, кнопка записи меняется на «Записаться в лист
  ожидания»; при отмене чужой брони первый в очереди получает место автоматически
  (логика бэкенда).
- **Правило 24 часов.** Отмена подтверждённой брони скрывается, если до начала
  МК осталось меньше 24 часов (константа `CANCEL_DEADLINE_HOURS` в
  `src/utils/constants.js` должна совпадать с бэкендом).
- **Статусы.** Все статусы МК/броней/действий выводятся цветными бейджами
  (единый справочник в `src/utils/constants.js`).
- **Форматирование.** Даты, длительность и цены форматируются средствами
  `Intl` на русском языке, без внешних библиотек.
